💬 **Question**: What is the compound components pattern in React, and what two problems does it solve?

---

⭐️ **Answer**: The **compound components pattern** is a design pattern in React where multiple components work together to form a single functional unit, sharing an implicit state while maintaining a clean, declarative API for the consumer. Think of it like the native `<select>` and `<option>` tags in HTML—the parent manages the state, and the children interact with it without needing to pass props manually through every level.

**The two main problems it solves are:**

*   **Prop Drilling:** It eliminates the need to pass state and event handlers down through multiple layers of intermediate components. By using React's `Context API` internally, the parent component provides the necessary state directly to its children, regardless of how deeply they are nested.
*   **Inflexible APIs (Component Bloat):** It prevents the creation of "God components" that require a massive, complex configuration object or dozens of props to handle every possible UI variation. Instead, it allows the consumer to compose the component structure declaratively, giving them more control over the layout and order of elements while keeping the implementation details encapsulated within the parent.

💬 **Question**: What is the difference between `useLayoutEffect` and `useEffect` in React, and when should you use `useLayoutEffect`?

---

⭐️ **Answer**: The primary difference lies in **when** they are executed in the React rendering lifecycle:

*   **`useEffect`**: This is **asynchronous**. It runs *after* the render is committed to the screen and the browser has painted the changes. This makes it ideal for most side effects, like data fetching, setting up subscriptions, or logging, because it doesn't block the browser from updating the UI.
*   **`useLayoutEffect`**: This is **synchronous**. It runs *after* React performs DOM mutations but *before* the browser paints those changes to the screen. React waits for the code inside `useLayoutEffect` to finish before updating the visual display.

**When to use `useLayoutEffect`**:
You should use `useLayoutEffect` only when you need to perform DOM measurements or mutations that must be visible to the user immediately to avoid a "flicker" or visual glitch. Common use cases include:
*   **Measuring DOM elements**: Getting the exact width, height, or scroll position of an element before the user sees it.
*   **Synchronous DOM mutations**: If you need to change the DOM based on those measurements (e.g., positioning a tooltip or a popover) before the browser paints, `useLayoutEffect` ensures the user doesn't see the element in its "wrong" position for a split second before it jumps to the correct one.

**Summary**: Always default to `useEffect` for performance reasons. Only reach for `useLayoutEffect` if you notice visual inconsistencies or need to perform layout-critical DOM operations.

💬 **Question**: What is code splitting in React, and how does `React.lazy` with dynamic `import()` enable it?

---

⭐️ **Answer**: Code splitting is a performance optimization technique that involves breaking your application's bundle into smaller, manageable chunks that are loaded **on-demand** (lazy loading) rather than loading the entire application code upfront.

*   **How it works**: By default, bundlers like Webpack or Vite bundle the entire application into a single large JavaScript file. As your app grows, this file becomes massive, leading to slow initial load times.
*   **`React.lazy`**: This function allows you to render a dynamic import as a regular component. It tells React to only load the component's code when it is actually needed (e.g., when a user navigates to a specific route).
*   **Dynamic `import()`**: This is the underlying JavaScript feature that triggers the bundler to split the code. When the browser encounters `import('./MyComponent')`, it initiates a separate network request to fetch that specific chunk of code.
*   **`Suspense`**: Since the component is loaded asynchronously, you must wrap the lazy-loaded component in a `<Suspense>` component, which provides a fallback UI (like a loading spinner) while the chunk is being fetched.

**🔑 Key Steps**:
*   Use `const MyComponent = React.lazy(() => import('./MyComponent'));` to define the lazy component.
*   Wrap the component in `<Suspense fallback={<Loading />}>` to handle the loading state.
*   This significantly improves the **Initial Page Load** time and reduces the amount of data the user needs to download to start interacting with the app.

- When React renders `LazyComponent`, it triggers the dynamic import.

- Once loaded, the component renders normally.
- This reduces the initial bundle size and improves app responsiveness.

💬 **Question**: What is derived state in React, and why is storing it as a separate state variable considered an anti-pattern?

---

⭐️ **Answer**: Derived state is any data that can be calculated or computed directly from existing props or state during the render process. Storing this as a separate state variable is considered an anti-pattern because it creates "source of truth" synchronization issues.

*   **What is Derived State?** It is data that is not independent. For example, if you have `firstName` and `lastName` in your state, the `fullName` is derived state. You don't need to store `fullName` in a separate `useState` hook; you can simply calculate it as `const fullName = firstName + ' ' + lastName;` inside your component body.
*   **Why is it an Anti-Pattern?**
    *   **Redundancy:** You are storing the same information in two places.
    *   **Synchronization Bugs:** If you update `firstName` or `lastName`, you must remember to manually update `fullName` as well. If you forget, your UI will display inconsistent or stale data.
    *   **Memory/Performance:** It increases the complexity of your state management and requires extra `useEffect` hooks or event handlers just to keep the derived value in sync, which is unnecessary overhead.

💬 **Question**: What is a protected route in React Router, and how would you implement route-level access control?

---

⭐️ **Answer**: A protected route is a wrapper component used to restrict access to specific parts of an application based on a user's authentication status or authorization level. If a user is not authenticated, the route redirects them to a login page or an unauthorized access page; otherwise, it renders the requested component.

**🔑 Key Steps**:
*   **Create a Wrapper Component**: Build a `ProtectedRoute` component that accepts the target component as a child or prop.
*   **Check Authentication**: Inside the wrapper, verify the user's authentication status (e.g., checking a token in local storage, a context provider, or a global state like Redux).
*   **Conditional Rendering**: 
    *   If authenticated, render the `children` (the protected component).
    *   If not, use the `Navigate` component from `react-router-dom` to redirect the user to the login page.
*   **Route Configuration**: Wrap your sensitive routes in the `ProtectedRoute` component within your main router configuration.

**💻 Code**:
```javascript
import { Navigate, Outlet } from 'react-router-dom';

// ProtectedRoute component to wrap sensitive routes
const ProtectedRoute = ({ isAuthenticated, children }) => {
  // If not authenticated, redirect to login
  if (!isAuthenticated) {
    return <Navigate to="/login" replace />;
  }
  
  // If authenticated, render the child component
  return children ? children : <Outlet />;
};

// Usage in Router configuration
<Routes>
  <Route path="/dashboard" element={
    <ProtectedRoute isAuthenticated={user.isLoggedIn}>
      <Dashboard />
    </ProtectedRoute>
  } />
</Routes>
```

**💡 Explanation**:
*   **Single Source of Truth**: By centralizing the logic in a `ProtectedRoute` component, you ensure consistent access control across the entire application.
*   **Declarative Routing**: Using `react-router-dom`'s `Navigate` component makes the redirection logic clean and declarative.
*   **Scalability**: This pattern can easily be extended to support role-based access control (RBAC) by passing a `requiredRole` prop to the `ProtectedRoute` and checking it against the user's profile.

- Define a `ProtectedRoute` component that accepts the component to render and the user’s auth/role info.

// ProtectedRoute component for route-level access control
